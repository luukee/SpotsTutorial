SPOTS Signup and Login

Staff reference for how REDCap email_primary and spots_user_id affect Google and password sign-in on spotsymptoms.org. This page is unlisted — share the URL only with study staff.

Written for UTH study staff answering onboarding questions. Prefer the participant-facing wording below when talking with families.

Signup — User ID vs Email

On email/password signup, families see two different boxes. They are not interchangeable.

Signup form fields and what to enter
Box on signup What to enter
User ID The value in REDCap spots_user_id (usually a username staff created, e.g. smith_parent). Families should not invent this.
Email The email they will sign in with. For the usual family case, this matches REDCap email_primary.
Password One the family creates.

Child logs in alone with their own email: staff put the child’s email in that child’s spots_user_id, keep the parent email on email_primary, and the child enters that same child email in both User ID and Email at signup.

Google: no User ID box — they use Sign in with Google with the matching email. Still tell password-signup families to enter the User ID staff gave them (do not say “Google doesn’t need a User ID”).

How login matching works

After someone signs in, SPOTS gets their account email from UTHealth AWS Cognito (the auth system for spotsymptoms.org). That email is looked up in REDCap against email_primary or spots_user_id. There is no separate “Cognito email” field in REDCap — Cognito is only where the signed-in email comes from before we check REDCap.

Quick answers

Is the signup User ID supposed to be a username or an email?
Usually a username from REDCap spots_user_id. Use an email in User ID only for the child-alone case (same child email in User ID and Email).
Can a parent and child share the same email_primary and both report?
Yes. That is the normal design. After sign-in they get the Reporting as screen and pick Parent or Child.
Do we need a new REDCap email field for parent automated emails?
No. Keep using email_primary for assent, gift cards, and other parent emails.
When should a child’s own email go in spots_user_id?
Only if that child should sign in alone with their own email (including Google). Parent email stays on email_primary so automated parent emails still work.
Can that child use Sign in with Google?
Yes, if their Google account email matches the child’s spots_user_id. Only the child record matches, so they go straight into the child’s account (no profile picker).
Does capitalization matter in spots_user_id?
Login matching is case-insensitive. Still enter emails in lowercase for consistency elsewhere in REDCap.

Suggested wording for families

  • Sign in with the same email that’s on their SPOTS record (Google or password).
  • For email/password signup, enter the User ID staff gave them, plus their email and a password.
  • If parent and child share one email, after login they choose Parent or Child.

Keep REDCap field names (email_primary, spots_user_id) and Cognito details for staff setup talk — families only need the email and User ID steps above.
